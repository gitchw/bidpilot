# 标擎 BidPilot v0.8.0 产品重审

## 结论

v0.8.0 把“渠道选择”升级为可运营的交付控制塔。核心差异不再是多放几个 Webhook，而是将一次运行拆成可审计的“运行 × 目标”任务：先持久化、分别发送、分别确认、分别重试、分别进入死信。用户在网页就能看懂哪个渠道成功、哪个还会自动重试、哪个需要修复，以及如何只恢复失败目标。

这轮同时把 Telegram Bot 与 Slack Incoming Webhook 接到官方公开接口，并诚实展示各自文件/链接边界。系统不通过绕过访问控制来制造覆盖量，也不把外部网络的至少一次语义宣传成绝对恰好一次。

AI 侧修复了“解析预览正确、真正执行再次询问模型后漂移”的根本问题：预览签发 15 分钟 HMAC 意图快照，立即执行、普通订阅、买方监控和订阅规则编辑都先展示主题、地域、时间与计划，再直接使用用户确认字段。产品也把 `检索部分覆盖` 与 `部分渠道待处理` 分开显示，避免一个 `partial` 同时代表数据覆盖和推送故障。

## 完整用户旅程

1. 用户输入自然语言，检查主题、地域、时间、计划和字段级解释；服务签发与完整确认意图绑定的限时快照。
2. 用户在首页看到全部目标和“文字 / Word / 链接”能力。
3. 未配置目标提供“去配置”，准确跳到对应卡片。
4. Telegram/Slack 卡的“设置报告链接”准确定位独立“报告发布与下载链接”卡；它们不再借用飞书配置。
5. 每张卡只保存自己的脏字段；敏感值加密且永不回显。
6. 用户先保存，再二次确认真实测试。
7. 即时任务、普通订阅、买方监控或订阅规则编辑同时使用多目标能力；执行或保存端验证快照后不再二次调用模型。
8. 报告、全部 Outbox 和目标公告集合在首次外发前原子落库。
9. 运行结果显示逐目标回执；成功目标不会因其他目标失败重发。
10. 订阅卡分别显示“检索部分覆盖”和“部分渠道待处理”；交付控制塔展示 pending、sending、retrying、succeeded、dead_letter、skipped。
11. 用户修复配置后，在即时结果页或订阅日志只重新排队指定死信，不重新抓取或重发成功目标。

## 可靠性与安全边界

- 数据库内成功状态与目标级公告账本原子提交。
- 多 worker 使用租约、lease token 栅栏和过期接管，旧进程不能覆盖新所有者。
- 本地重试按 60 秒、5 分钟、15 分钟、1 小时、3 小时基准加入正向有界抖动，最多 10% 且不超过 60 秒；平台 `Retry-After` 取更晚时间，不会被本地上限提前截断。
- 永久认证、权限、目标 ID 错误第一次即进入死信；临时网络错误最多五次。
- 独立 worker 在检索和 Outbox 外发前重新加载网页配置；另一进程恢复默认值后不会继续使用旧目标。
- `server.json` 原子独占创建，第二个 `serve` 无法覆盖首个可管理实例；真实运行端点与已保存重启值分开显示。
- worker 取消会把自己的活跃运行标记为失败并释放自身租约，新 worker 可立即接管，旧 lease token 不能覆盖新所有者。
- 意图快照绑定规范化原问题和完整结构化字段；问题改变、篡改或过期返回 409，订阅创建成功后确认字段持久化。
- Telegram Token、Slack Webhook、SMTP 密码、API Key 和 Cookie 不进入 API 读取、错误、日志或 Git。
- Slack 用户可控标题会转义 `&<>`，不会触发 `<!channel>` 或 `<@用户>` 意外提及。
- 不绕过验证码、WAF、付费墙、账号角色、CA、频率限制或站点条款。

## 渠道产品定位

- Telegram：直接发送普通 Word，支持话题、静默和内容保护；超过 50 MB 时只有在安全公网地址存在时才改发链接。
- Slack：商业版 `hooks.slack.com` 和 GovSlack `hooks.slack-gov.com` Incoming Webhook 只发送消息和链接；不伪装支持附件。未来文件上传必须另建 Bot Token 和权限模型。
- 飞书应用、邮件：适合直接文件交付。
- 飞书/钉钉/企微/Slack Webhook：适合群消息和安全报告链接。
- 通用 Webhook：面向 n8n、Make 或自建自动化，接收端负责业务幂等。
- 报告中心：永远可用的本地兜底，不主动外发。
- 报告发布卡：不是渠道，而是多个链接型渠道共用的安全 `public_base_url`；只有已有 TLS、身份认证和访问控制时才允许面向公网使用。

## 下一版优先级

1. AI 订阅沙盘：保存前基于本地历史证据估算命中量、噪声和覆盖缺口，建议由用户确认后应用。
2. 变化指纹：确定性比较金额、截止时间、采购人、附件和阶段，再由 AI 把真实 diff 改写成中文。
3. 订阅覆盖体检：把来源健康、授权状态和近七日产出绑定到每条订阅，覆盖退化时单独提醒。
4. 分级通知：高适配/临近截止立即推送，普通结果每日汇总，全部结果留本地，并支持静默时段。
5. 多用户协作必须等待真正的身份、角色、审计和权限基础设施，不在当前 LAN 信任模型上仓促叠加。
