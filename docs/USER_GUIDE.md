# 标擎 BidPilot 用户操作手册

本手册适合已经完成安装的日常用户。如果你不知道“终端”“项目目录”或 `127.0.0.1` 是什么，请直接阅读 [《零基础操作说明书》](BEGINNER_MANUAL.md)，其中包含逐命令安装、启动、状态、停止、重启、备份、恢复和卸载步骤。

## 1. 产品能做什么

标擎把一句中文需求变成可执行的招投标情报任务：

- 理解主题、城市/省份、时间范围、公告类型、排除词和发送计划；
- 访问多个公开或用户主动授权的免费会员来源；
- 严格过滤、跨站去重并关联项目生命周期；
- 生成带原文链接与证据片段的 Word 报告；
- 把真实标讯加入机会工作台；
- 长期订阅只提醒尚未成功投递的公告版本；
- 通过飞书、邮件、钉钉、企业微信或通用 Webhook 推送。

系统不会用演示假数据填充结果，不绕过验证码、付费墙、登录权限、频率限制或平台访问控制。

## 2. 启动

首次安装：

```bash
python bootstrap.py
```

启动 Web 与内嵌长期任务 worker：

```bash
python -m bidpilot serve
```

常用生命周期命令：

```bash
python -m bidpilot status   # 查看 Web、worker 和订阅状态
python -m bidpilot stop     # 优雅停止，保留数据库、订阅和报告
python -m bidpilot restart  # 先停止，再在当前终端前台启动
```

打开：

- Web：`http://127.0.0.1:8000`
- 中文 API 文档：`http://127.0.0.1:8000/docs`

默认只允许本机访问。项目不依赖 PowerShell 服务脚本，Windows、macOS 和 Linux 使用同一组 Python 命令。

## 3. 情报检索

### 3.1 写一个好问题

推荐结构：

```text
时间范围 + 地域 + 主题 + 公告范围 + 排除条件 + 发送计划 + 通道
```

示例：

```text
最近1个月深圳充电桩招标信息
过去90天北京GPU服务器采购，排除运维服务
上周杭州UPS更正公告
2026年第二季度浙江云服务合同公告
每周五下午3点发送广东数据中心标讯到飞书
每月最后一天18点发送广东数据中心信息到邮箱
```

### 3.2 先点“解析意图”

界面会展示：

- 主题；
- 地域；
- 时间窗口；
- 计划；
- 置信状态和警告。

例如 `最近1个月深圳充电桩招标信息` 应显示：

```text
主题：充电桩
地域：深圳
来源地域代码：440000（内部字段）
计划：立即执行
警告：无
```

若仍看到“主题：深圳充电桩、地域：全国”，说明浏览器可能连接旧进程或旧静态缓存。先运行 `python -m bidpilot status`，确认服务版本为 v0.5.0，再执行 `python -m bidpilot restart` 并刷新页面；当前解析器版本应为 `hybrid-v1`，规则基线版本为 `rules-v2`。

### 3.3 公告类型规则

- “服务器招标信息”“采购信息”：默认保留全部生命周期，不只看招标公告。
- “只看招标公告”：只保留招标公告。
- “中标公告”：只保留中标/成交结果。
- “更正公告”：只保留更正、变更、澄清。
- “招标和中标公告”：保留招标和中标两类。
- “排除中标公告”：作为排除条件处理，不会错误地同时只看中标。

### 3.4 启动情报任务

点击“启动情报任务”后，界面依次显示理解意图、多源采集、可信聚合和生成报告。完成后可看到：

- 可信结果数；
- 高优机会数；
- 项目生命线数；
- 合并重复数；
- 每个来源的扫描/候选/保留与中文状态；
- 标题、公告类型、日期、地域、采购人、摘要、评分和原文链接。

结果为 0 也可能是可信结果；系统不会用无关标讯凑数。此时按以下顺序判断：

1. “扫描”表示从来源列表读取的公告；“候选”表示进入统一证据核验；“保留”才是最终可信结果。
2. 查看“为什么一条也没留下”，区分地域不匹配、超出时间、主题未命中、公告类型不符和命中排除词。
3. 查看“为什么不能简单理解成全网没有”。“覆盖不完整”“需要登录”“抓取失败”都代表本轮存在覆盖缺口。
4. 可点击“扩大到最近 3 个月”“临时改为全国”或“改用同义词”。按钮只填入问题，不会自动查询；请先重新解析意图，再决定是否执行。

## 4. Word 报告

即时任务无论是否保留到可信结果，都会生成 Word：有结果时写入结果明细，0 条时写入扫描漏斗、排除原因和覆盖边界。文件名格式：

```text
{用户问题}_{yyyyMMddHHmm}.docx
```

报告包含：

- 查询口径；
- 执行摘要；
- 来源覆盖与失败披露；
- 结果明细；
- 原文 URL；
- 证据片段与附件。

可在结果页或“报告历史”下载。长期订阅本轮无新增时，可能不生成新 Word；系统仍会记录运行回执，并按“仍发送运行回执/保持安静”策略处理外发。

## 5. 长期订阅

### 5.1 创建

问题中包含每天、每周、每月或未来某时发送计划。解析后点击“创建并验证订阅”。

支持：

- `每天早上八点半`；
- `每周五下午3点`；
- `每月1日上午9点`；
- `每月最后一天18点`（短月自动落到月末）；
- `明天下午2点` 的一次性任务。

创建后先写入 SQLite，再由 worker 领取。浏览器关闭、页面刷新或进程重启不会让订阅消失。

### 5.2 为什么点击后看起来“没有下文”

进入“订阅中心”检查：

- “长期任务服务在线”：worker 正常；
- “下次执行”：任务何时到期；
- “待领取”：已到期，等待 worker；
- “执行中”：有活跃租约；
- “等待重试”：上轮失败，系统已安排退避；
- “已暂停”：不会自动执行。

点击“日志”查看每一轮运行和投递回执。系统不会仅靠前端定时器假装后台任务存在。

### 5.3 管理操作

- 立即执行：与 worker 互斥地手动运行。
- 暂停后续：保留规则和账本。
- 恢复：重算下一次时间，可选择是否立即跑。
- 编辑规则：保留既有成功投递账本，避免重复。
- 修改交付/无新增策略。
- 删除：需二次点击，会删除订阅增量账本；不可逆。

### 5.4 无新增策略

- “仍发送运行回执”=`always`：每轮都有完成证明。
- “保持安静”=`on_change`：只有新增才外发，但运行日志仍更新。

## 6. 配置中心

进入“配置中心”，可管理：

- OpenAI-compatible 模型；
- 飞书群机器人；
- 飞书应用；
- SMTP 邮件；
- 钉钉群机器人；
- 企业微信群机器人；
- 通用 Webhook。

操作原则：

- 点击“保存全部配置”立即生效；
- 密钥输入框永远不回填原文；
- 留空保持原值；
- 勾选清除才删除；
- 模型测试会调用固定测试句；
- 通道测试会真实外发，网页会先确认。

详细字段与安全说明见 [CONFIGURATION_GUIDE.md](CONFIGURATION_GUIDE.md)，各平台投递语义见 [DELIVERY_CHANNELS.md](DELIVERY_CHANNELS.md)。

## 7. 机会工作台

只有当前运行结果中的真实标讯可以“加入机会”。系统不接受客户端自造标题、采购人或摘要。

机会按项目而不是公告管理：

- 同项目重复加入不会制造重复销售线索；
- 新更正/中标公告会刷新项目快照并标为未读；
- 人工设置的阶段、负责人、下一步、标签和备注不会被刷新覆盖；
- “生命周期”可查看同项目全部已抓取事件和原文证据。

阶段：待评估、跟进中、投标准备、已中标、未中标、已归档。

## 8. 来源中心

来源中心展示：

- 官方/行业来源；
- 公开/授权模式；
- 是否可运行；
- 最近检查；
- 抓取/保留数量；
- 失败或授权诊断。

千里马等会员增强源只使用用户主动登录后保存在本机的免费会员会话，不保存密码。登录命令：

```bash
python -m bidpilot auth qianlima
```

需要验证码时由用户在浏览器主动完成；系统不会绕过。

## 9. 常见问题

### 地域没有识别

1. 点击“解析意图”，确认是否仍有“未识别到明确地域”警告。
2. 对直辖市、省份和常见城市直接写全称，如“深圳”“苏州”“内蒙古自治区”。
3. 确认 API 返回 `parser_version=hybrid-v1`；其中规则基线版本仍为 `rules-v2`。
4. 重启服务并强制刷新浏览器。
5. 把失败原句加入 `tests/test_intent.py` 的字段级回归矩阵，再修规则，避免只做一次性补丁。

### 订阅存在但不自动执行

- 检查订阅中心 worker 状态；
- 若使用独立 worker，启动 `python -m bidpilot worker`；
- 检查 `next_run_at` 是否尚未到期；
- 查看日志是否在退避重试；
- 不要同时启动多个内嵌 worker 与独立 worker，虽然租约会防重，但会增加无效竞争。

### 通道下拉框是灰色

必填配置尚未满足。到配置中心保存后，系统状态和下拉框会立即刷新。

### 模型失败会不会导致任务失败

不会。模型摘要失败会自动回退到本地证据抽取。来源、报告或投递失败仍按真实状态披露。

### 为什么普通“招标信息”会看到中标/更正

这是项目生命周期设计。普通表达默认不做公告类型硬过滤；要限制时写“只看招标公告”。

## 10. 数据与备份

重要目录：

```text
data/bidpilot.db                       订阅、运行、结果、机会、配置
data/secrets/runtime_config.key       敏感配置解密密钥
outputs/reports/                      Word 报告
```

备份数据库和密钥时保持同一时间点。不要只复制数据库后丢弃密钥。

## 11. 合规边界

允许：

- 公开网页和官方 API；
- 用户主动授权的免费会员会话；
- 合理缓存、明确 User-Agent、有限超时与重试；
- 按平台公开文档接入机器人和应用。

禁止：

- 绕过验证码；
- 绕过付费墙或会员权限；
- 窃取 Cookie、密码或身份凭据；
- 规避频率限制和访问控制；
- 伪造来源、结果或投递成功；
- 把敏感配置写入 Git、报告、截图或日志。
