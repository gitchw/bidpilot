# 超聚变命题交付与验收清单

团队：聚标成擎｜作品：标擎 BidPilot｜版本：v0.8.0｜更新：2026-08-11

## 1. 官方交付物逐项对照

| 官方要求 | 终版目录 | 交付前检查 |
|---|---|---|
| 多份运行结果 Word | `01_运行结果Word/` | 文件名按“用户问题_时间”；至少覆盖两个不同问题，并包含正向、零结果或来源受限记录 |
| 详细设计文档 | `02_设计文档/详设文档.docx` 与 `.md` | 业务流程、数据对象、来源边界、增量账本、部署、评价和未完成项齐全 |
| 完整源码与安装/验证文档 | `03_代码与操作文档/` | 源码可从当前提交安装；不含 `.env`、数据库、Cookie、密钥、浏览器 profile 和旧交付目录 |
| 覆盖多个问题、输入到输出全流程的 Demo 视频 | `04_Demo/` | 本地 MP4 已完成并纳入交付包；上传后再回填经未登录窗口验证的公开链接 |

当前成片 172 秒，覆盖检索口径、真实执行、Word 下载、定时订阅和第二轮零新增证据；公开链接仍须上传后用未登录窗口复核。

## 2. 运行结果 Word 的字段验收

非零报告每条结果必须能找到：

- 标题、发布时间、地域、采购单位和公告类型；
- 核心内容与至少一个来源名称、来源链接；
- 附件名称和链接，或明确“原文未发现可公开下载附件”；
- 访问范围（公开信息 / 免费会员列表可见）；
- 运行口径、来源覆盖、去重数量和证据片段。

零结果报告不要求伪造来源链接，但必须保留来源状态、扫描 → 候选 → 保留漏斗、淘汰原因和覆盖缺口。终版已包含同一订阅的双轮真实证据：首轮 57 条并生成 Word，第二轮检索同一批记录后 `new_count=0`、不生成空 Word、Outbox 记录为跳过，版本账本仍为 57 条。两轮 ID、数据库快照和 API 回读位于 `05_验收与校验/真实订阅增量证据/`，不能只用代码实现代替运行证据。

## 3. 录制与截图验收

录制主线使用一家服务器解决方案团队的情报专员：

1. `最近一年广东省服务器招标信息`：即时解析、来源覆盖、结果卡、Word、加入机会；
2. `最近3个月上海充电桩招标信息，请每天9:00汇总后发送给我`：定时解析、创建订阅、下次执行、仅新增账本；
3. 可选短证据：千里马已验证或需重新登录状态、Linux `/health`、systemd/Compose 拓扑。

截图应优先保留：查询口径、正向结果、来源状态、机会卡、订阅日志和投递回执。不要用只有菜单或大段架构文字的截图代替结果画面。

## 4. 安全与授权边界

- 仅使用公开信息或用户本人主动授权的免费会员可见范围；
- 不绕过验证码、WAF、付费详情、CA、角色或频率权限；
- 不导出或打印 Cookie、密码、Token、Webhook、私钥、浏览器 profile 路径和个人账号信息；
- 千里马会员监控默认关闭；开启前必须登记书面授权或官方 API 编号；
- 企业服务器通过 HTTPS 网关访问，后端 8000 不直接暴露公网；
- 视频和 Word 中的账号、令牌、内网地址均需遮挡。

## 5. 安装与跨平台检查

在 Windows、macOS、Linux 各使用一次项目解释器完成：

```text
python bootstrap.py --dev
{PY} -m bidpilot serve
{PY} -m bidpilot status
{PY} -m bidpilot parse "最近1个月安徽服务器招标信息"
{PY} -m bidpilot stop
```

Linux 额外检查：

```text
sudo systemctl status bidpilot-web
sudo systemctl status bidpilot-worker
curl -fsS http://127.0.0.1:8000/health
```

企业 Compose 只在有 Docker 的环境实跑；没有 Docker 的开发机不得在材料中写“本机 Compose 已通过”。

## 7. 不能由代码自动填入的信息

- 参赛成员真实姓名：以比赛报名表为准；材料只写真实职责；
- Demo 公开视频链接：录制、上传、未登录窗口验证后由团队回填；
- 生产 HTTPS、证书、SSO/RBAC 和公网入口：在目标企业环境验收后再填写，不使用虚构地址或测试账号；
- 业务效率、覆盖率、转化率：作为 4 周试点指标，先冻结人工基线，不写成既有客户成绩。

## 8. 交付前十分钟

1. 用 Microsoft Word 打开方案、详设和运行结果，确认没有“填写内容、提交时删除、Timer”等模板提示；
2. 从交付目录打开一份正向 Word，点击来源链接并回到原文；
3. 打开零结果或来源受限 Word，确认没有“全网无结果”的误导性结论；
4. 打开交付包内本地 MP4 核验播放；上传后，再在未登录浏览器窗口验证公开视频链接；
5. 对交付目录重新生成文件清单和 SHA256，记录最终 commit、测试记录和 CI 链接。
