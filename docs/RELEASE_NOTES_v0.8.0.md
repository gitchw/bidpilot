# 标擎 BidPilot v0.8.0 更新说明

发布日期：2026-08-13
适用对象：招投标情报专员、业务负责人、系统管理员、比赛评审与交接维护人员

## 这次更新解决了什么

v0.8.0 把产品从“能检索和生成报告”推进到一套可以长期使用、能说明结果来源、能把信息交给下一位责任人的招投标情报工作流。

用户现在可以输入一句中文需求，先确认主题、地域、时间和计划，再执行即时查询或创建持久计划任务。结果按业务优先级展示，同时保留来源状态、筛选漏斗、原文和证据。定时任务只处理新公告或新版本，Word、投递状态和项目跟进都能回到同一条真实记录。

## 本轮主要更新

### 1. 首页与导航重新设计

- 首页价值表达改为“把分散公告，变成能跟进的项目”，先讲用户动作和结果。
- 七个区域统一为：查找情报、判断与复盘、机会跟进、自动订阅、来源状态、系统设置、Word 报告。
- 新增“继续上次工作”，直接回到最近报告、待跟进机会和运行中的订阅。
- 结果卡优先展示标题、采购人、日期、地域、访问范围、来源名称和业务动作；检索技术轨迹移到结果之后。
- 桌面、1024px 平板和 390px 手机布局均已验收；主导航支持键盘方向键、Home/End、ARIA 状态和减少动效。

### 2. 即时查询与计划任务不再混淆

- 即时问题的主按钮直接执行检索。
- “明天 9 点”、每天、每周、每月等计划问题的主按钮创建持久任务，不会误当即时查询。
- 创建前仍展示已解析的主题、地域、时间、计划和投递方式；确认快照会防止保存时二次解析漂移。

### 3. 千里马免费账号登录适配

- 用户本人在运行 BidPilot 的电脑上完成可见登录，系统复用同一个持久浏览器 profile。
- 已真实验证免费会员列表检索：最多 2 页、40 条，并保留冷却、每日预算、跨进程锁和登录健康检查。
- Linux 无图形后台可复用已经验证的 profile 运行有界 headless 查询；登录失效时立即降级并提示重新登录。
- 不导出或重放 Cookie，不绕过验证码、WAF、付费详情或会员等级；定时会员监控默认关闭，必须另有书面授权或官方 API 记录才可开启。

### 4. 报告与来源披露更清楚

- Word 结果标题使用“结果 01、结果 02……”并避免标题拆页。
- 每条记录显示真实来源名称及“公开信息 / 免费会员列表可见”，不再只写“来源 1”。
- 保留查询口径、来源扫描/候选/保留、淘汰原因、原文、附件和证据片段。
- 0 条结果仍生成可核验说明，不用无关公告填充。

### 5. 从结果进入业务跟进

- 真实标讯可加入机会，保存阶段、负责人、下一步动作、计划时间、标签、备注和已读状态。
- 后续更正、中标或合同公告更新项目证据时间线，不覆盖人工跟进字段。
- 买方雷达只聚合本机已经保存的真实公告，可据此创建采购单位锁定的长期监控。
- 企业画像、证据约束适配判断、本轮问答和人工反馈记忆共同支持“参与 / 观察 / 跳过”判断。

### 6. 订阅、增量和投递可靠性

- SQLite 持久保存订阅、下次执行时间、worker 心跳与租约、运行历史、公告版本账本和逐目标 Outbox。
- 报告和投递任务先落库；一个渠道失败不会拖着成功渠道重复发送。
- 失败目标有限重试并进入死信，可只恢复该目标，无需重新抓取。
- 真实双轮证据已完成：首轮新增 57 条并生成 Word；第二轮再次命中同一批记录但新增 0 条，不生成空 Word，账本仍为 57 条。

### 7. 企业 Linux 与跨平台运行

- 原生 Python、Docker Compose 和 systemd 均有安装、启动、状态、停止和故障排查文档。
- 企业模式通过 HTTPS 网关、受信代理、精确 Origin、私网客户端和管理员令牌控制访问；后端 8000 不直接暴露公网。
- GitHub Actions 覆盖 Windows、Ubuntu、macOS × Python 3.11/3.13，以及 Ubuntu 企业 HTTPS 容器，共 7 个作业。
- 本地完整测试为 311 项；最终 `main` 的跨平台 7/7 运行链接与精确提交信息见《跨平台测试与发布审计》和交付包构建信息。

## 目前已经具备的功能

- 中文意图：主题、同义词、地域、时间、公告类型、排除词、采购单位、即时/一次/每日/每周/每月计划。
- 多源检索：10 个真实来源适配器，逐来源失败隔离和诊断。
- 内容处理：正文与附件提取、硬过滤、可选语义复核、跨站去重、生命周期聚合、机会评分。
- 可选 AI：意图补全、检索规划、边缘候选复核、证据约束摘要、企业适配和本轮证据问答；失败时确定性降级。
- 交付：Word、本地报告中心、飞书机器人/应用、SMTP、钉钉、企业微信、通用 Webhook、Telegram、Slack。
- 管理：自动订阅、运行日志、逐目标回执、死信恢复、机会卡、买方雷达、企业画像、反馈记忆、来源状态和系统设置。
- 运维：Web/API/CLI、SQLite、跨进程租约、重启补跑、Docker、systemd、企业 HTTPS 网关。

## 升级与使用提示

1. 拉取 `main` 后执行 `python bootstrap.py --dev`，让当前虚拟环境补齐依赖。
2. 使用 `python bootstrap.py --auth` 启动可管理来源登录的服务；需要千里马增强时，在“来源状态”中由账号本人完成免费登录并测试。
3. Linux 后台部署按 `docs/LINUX_DEPLOYMENT.md` 选择 systemd 或 Compose，不要直接把 8000 暴露公网。
4. 已有 SQLite 数据、`.env`、`data/secrets/` 和浏览器 profile 不需要删除，也不得提交到 Git。

## 已知边界

- 外部网站可能改变 DOM、WAF、验证码或服务策略；来源状态必须以当轮诊断为准。
- 普通 Webhook、SMTP 和消息平台属于外部至少一次投递，极小的“平台已收、本机未写回”窗口可能产生一次重复。
- 当前内置访问控制适合本机、可信内网和企业网关后的管理使用，不是完整多租户 SSO/RBAC 产品。
- 公网 Demo 链接需要团队上传后用未登录窗口验证；交付包已经包含可播放的本地 MP4，不虚构外部地址。
- 业务效率、覆盖率和转化率仍需在真实企业 4 周试点中建立基线，不作为既有客户成绩宣传。
