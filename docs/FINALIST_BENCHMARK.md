# 超聚变入围作品观察与 BidPilot 打磨记录

编制日期：2026-08-11｜用途：产品复盘与参赛材料校准

## 1. 我们从入围作品里看到了什么

用户提供的入围信息里，三条评语很值得借鉴：

- **TenderTrace** 被认可的地方是把方案处理的业务对象和执行动作说清楚，并且有完整的评价体系；
- **讯标雷达** 的亮点是国内招投标平台 API 定位、免费登录态、监控采集、定时推送和 Web 应用的真实落地，且“每条核心内容绑定原文片段、来源和附件”；
- **BidPilot** 的优势被概括为“构建可信的情报工作流”、10 个来源和可长期运行的工程建设。

这不是要把三个产品拼成一张功能表，而是提醒我们：评委先判断业务是否成立，再判断技术能否让它长期运行。材料和页面都应按“用户对象 → 执行动作 → 可核验产出”组织。

## 2. BidPilot 的取舍

### 保留并讲清楚

1. **从问题到责任人。** 结果不仅有链接，还能进入机会卡，保存负责人、下一步和计划时间。
2. **来源状态有层次。** 公开入口、已授权会话、会员增强和本轮实际贡献分开显示；登录失效不能变成假绿灯。
3. **长期任务可恢复。** SQLite、worker 租约、公告版本账本和逐目标 Outbox 让订阅在重启、单源故障和单渠道失败时仍可追踪。
4. **评价可复核。** 来源可用性、事实追溯、检索质量、工程可靠性和业务采用五层分开，业务数字只在真实试点后计算。

### 不照搬或不夸大

- 不把“免费登录态”写成获取付费详情或全站数据；
- 不把“10 个来源”写成覆盖全部公告；每个来源都有公开、授权、分页和频率边界；
- 不把审计同事写成核心研发主导；其真实贡献是授权矩阵、证据抽查、指标口径和交付清单；
- 不把“可配置渠道”写成已经有客户推送成绩；没有配置就显示未配置，没有回执就不说送达成功。

## 3. 这轮产品改动

### 首屏从宣传语改成工作承诺

原首屏强调“追踪每个真实商机”和技术标签。现在改成：

> 把分散公告，变成能跟进的项目。

说明文字直接告诉用户：输入一句需求后，系统会说明查了哪些来源、为什么保留或排除，并交付带原文链接的 Word 和下一步行动。静态“0 硬编码结果 / 100% 可回溯”改为可核验的接入来源、Word 交付和原文保留。

### 主路径只保留三步

首页默认显示查询框和“预览检索口径”；交付渠道移入折叠设置，报告中心作为默认目标。解析后的即时问题显示“开始查找”，每日/每周/每月问题显示“创建定时订阅”。一次性预约不通过未实现的快捷分流。

### 完成页先给答案

结果页顺序改为：完成状态与下载 Word → 来源覆盖 → 结果卡与加入机会 → 适配解释、问答、投递回执和检索轨迹。评委不需要越过长段技术说明才能看到第一条证据。

### 移动端和可访问性

390px 宽度下导航改为可横向滚动的 12px 触控项，不再把 7 个入口压成 8px；查询框排在营销说明之前。补充键盘左右/Home/End 导航、`aria-selected`、可见焦点、减少动效、来源卡三列栅格和真实禁用光标。

## 4. 五层评价矩阵

| 层级 | 当前可以现场复核 | 试点才会产生的数字 |
|---|---|---|
| 来源可用性 | 状态、授权时间、扫描/候选/保留、覆盖缺口 | 4 周来源可用率与授权失效恢复时间 |
| 情报可信度 | 页面、Word、原文标题/日期/链接逐条一致 | 随机样本字段可追溯率 |
| 检索质量 | 日期/地域/阶段硬过滤、跨站去重、零结果漏斗 | 冻结问题集的误保留与重复率 |
| 工程可靠性 | CI、Linux worker、Outbox 单目标重试与租约恢复 | 任务成功率、恢复时间和投递失败分布 |
| 业务采用 | 机会卡责任人和下一步是否能保存 | 首次检索耗时、有效机会确认和动作完成率 |

## 5. 评委现场的最短验证路线

1. 输入 `最近一年广东省服务器招标信息`，确认口径后执行；
2. 随机点开一条结果，核对访问范围、原文和附件；
3. 下载同一轮 Word，核对标题、日期、来源和核心内容；
4. 加入机会并填写下一步，刷新页面确认状态仍在；
5. 输入每日问题，确认主按钮创建订阅，查看下次执行和增量账本；
6. 打开来源状态，若千里马未验证，确认系统写“需重新登录”而不是“已授权”；
7. 在 Linux 或 CI 证据中查看 `/health`、worker 和企业网关边界。

## 6. 后续优先级

- 运行入库时生成统一、持久的 `evidence_id`，让结果卡、Word、问答和适配判断共享同一证据主键；
- 为机会字段增加追加式操作日志，记录操作者、时间和 from/to；
- 在自动订阅页面加入近 7 日来源覆盖体检，区分“0 条新增”和“来源失效”；
- 仅在真实样本中抽取预算、截止时间、采购方式和资格条件，并为每个非空字段保留原文证据；
- 试点后再决定移动端、RBAC、SSO 和数据库扩展，不把路线图写成当前能力。

这份观察的结论很简单：BidPilot 下一步要增加的不是更多名词，而是让评委更快看见“谁在什么时候根据哪条原文做了什么”。
