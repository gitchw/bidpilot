# 标擎 BidPilot 40 强赛 Demo 录制脚本

版本：v0.8.0｜更新：2026-08-11｜建议时长：4 分 30 秒左右

这是一条“一个情报专员完成两件事”的故事，不是菜单巡游。录制时只使用当前版本真实运行、真实报告和真实来源状态；如果网络或登录失效，就把失效状态说出来，切换到同一版本的历史运行记录，并在画面上标明“历史记录”。

## 录制前准备

- 准备一个正向问题：`最近一年广东省服务器招标信息`。
- 准备一个定时问题：`最近3个月上海充电桩招标信息，请每天9:00汇总后发送给我`。
- 预先确认报告中心可写入；外部飞书/邮件渠道没有配置时，不演示“发送成功”，只展示报告中心回执。
- 若展示千里马，使用用户本人在运行主机上完成的免费账号登录；遮挡账号、手机号、令牌、浏览器 profile 路径和内网地址。
- 录制前执行一次 `python -m bidpilot status` 和 `/health`，把版本、进程和时间写入录制台账。
- 不在录屏里输入或朗读密码、Cookie、Token、Webhook、私有服务器地址；不点击付费详情，不绕过验证码或 WAF。

## 0:00–0:25｜开场：今天要交付什么

画面：打开首页，保持查询框可见。

口播：

> 我今天扮演一家服务器解决方案团队的情报专员。我的交付不是一张链接清单，而是四个答案：找到了什么、为什么留下、原文在哪里、下一步谁来做。先用一个即时问题，再把第二个问题设成每天九点只发新增。

验收点：前 25 秒说清角色、问题和产出；不要先介绍模型或技术名词。

## 0:25–1:25｜问题一：从一句话到可核验结果

操作：

1. 在查询框输入 `最近一年广东省服务器招标信息`，点击“预览检索口径”。
2. 指认主题、地域、起止日期和“即时执行”；说明“确认前不会抓取”。
3. 点击“开始查找”，等待流水线完成。
4. 先看完成卡、结果数量和覆盖提示，再打开第一条结果。

口播：

> 页面先把“服务器、广东、最近一年”摊开。程序先锁定日期、地域和公告阶段，模型即使开启也只能建议同义词，不能改写 URL 或数字。现在结果已经完成，我先看项目，再看技术细节。

画面必须出现：

- 结果卡的标题、发布时间、采购单位、公告阶段、机会分；
- 来源名称和访问范围（公开信息或免费会员列表可见）；
- 至少一个可点击原文链接和附件状态；
- 来源覆盖条中的扫描 / 候选 / 保留数量。

## 1:25–1:55｜Word 与零结果：报告不替你补答案

操作：点击“下载 Word”，打开当前报告；随后回到页面（如果准备了零结果历史运行，可从 Word 报告页打开，不要伪装成刚刚在线运行）。

口播：

> Word 和页面使用同一批记录。非零报告逐条保留标题、发布时间、来源、原文和附件；原文没有附件就写明没有。零结果也不是一句“没有”，而是告诉我哪些来源完成、哪些被跳过，以及候选在哪个硬条件被排除。

验收点：报告文件名含用户问题和时间；非零报告可回原文，零结果报告保留扫描漏斗。

## 1:55–2:25｜千里马：合法复用用户本人免费会话

画面：切到“来源状态”，只显示授权状态和最近验证时间，不显示账号或 profile 路径。

口播：

> 这一路使用我本人的免费账号。首次登录在运行 BidPilot 的服务器可见浏览器完成；验证要同时通过页面状态和一次真实列表查询。后台只在账号原本可见的范围内做有界即时查询，有页数、结果数、冷却和每日预算。Cookie 不导出，不用 HTTP 重放，也不进入付费详情。今天如果会话失效，系统会显示“需重新登录”，公开来源仍然继续，不会拿旧缓存冒充成功。

操作：若状态为“已验证”，执行一次包含 `服务器` 的即时列表查询，指认结果卡“免费会员列表可见”；若状态不是已验证，展示状态和“重新登录”入口，明确这是诚实降级证据。

## 2:25–3:25｜把一条标讯交给业务同事

操作：在结果卡点击“加入机会”，进入“机会跟进”。打开“跟进设置”，填写一名负责人、下一步动作和计划时间，保存；再展开原公告时间线。

口播：

> 这张卡不是复制一段摘要。它引用已经保存的标讯，负责人、下一步和时间由人维护；后续更正或中标只更新证据时间线，不覆盖人的跟进记录。销售同事打开时，能直接回答“谁在什么时候做什么”。

验收点：阶段、负责人、下一步、计划时间、原文链接和时间线可见；不要把“建议参与”说成中标承诺。

## 3:25–4:05｜问题二：定时与仅新增

操作：回到首页，输入 `最近3个月上海充电桩招标信息，请每天9:00汇总后发送给我`。点击“预览检索口径”，指认频率；点击主按钮“创建定时订阅”。进入“自动订阅”，展示下一次执行、最近新增和报告/投递日志。

口播：

> 同一个主按钮会按计划类型分流：即时问题查一次，每日问题保存为订阅并交给 worker。订阅按“公告版本 × 交付目标”记账，第二轮不会把已经成功送达的旧版本再发一遍。报告中心默认保存 Word；外部渠道没有配置时，页面不会假装消息已经送达。

若已有两轮真实记录：展开日志，指认第一次新增数和第二次新增数；若没有，展示“首轮等待 worker”状态，并把“仅新增”作为下一次运行的验收动作，不朗读预测数字。

## 4:05–4:30｜Linux 与结尾

画面：展示企业部署拓扑、`/health` 输出或 systemd 状态截图；不要露出令牌、证书私钥和内网细节。

口播：

> 公司部署时，浏览器只到 HTTPS 网关，BidPilot Web 和 worker 在内网运行，8000 端口不直接裸露。Linux systemd 负责后台运行和重启，SQLite 保存任务、报告和投递账本。评委可以随机抽一条结果回到原文，也可以再跑一次订阅验证旧版本是否不再发送，这就是我们的验收标准。

## 录制后核对

- [ ] 两个问题都展示了从输入到输出的完整路径；
- [ ] 即时问题进入结果页，定时问题进入自动订阅，没有混用按钮；
- [ ] 至少一条结果能打开来源，Word 与页面字段一致；
- [ ] 免费登录来源状态与实际会话一致，不展示任何凭据；
- [ ] 失败、零结果、未配置渠道和历史记录均有明确标签；
- [ ] 视频公开链接只在真正上传并用未登录窗口验证后回填到 `视频公开链接.txt`。
