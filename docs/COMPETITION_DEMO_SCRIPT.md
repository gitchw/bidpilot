# 标擎 BidPilot 40 强赛 Demo 录制脚本与分镜

建议时长：5 分钟
录制原则：只展示本次现场真实运行；不展示或口播账号、手机号、Cookie、Token、数据库路径、私人采购信息或未脱敏文件。所有“通过”结论均以录制当次界面、命令输出或 CI run 为准。

## 录制主线

不要按技术菜单逐页介绍。以“业务对象 × 执行动作 × 结果责任”串起一条链：

`需求 → 检索任务 → 固定证据 → 企业机会与下一步动作 → 增量交付 → 审计复核`

开场标题：`标擎 BidPilot：把采购情报转为可复核的行动`
屏幕角标：`证据优先｜多来源｜机会动作｜Word｜安全部署`

## 0:00–0:30 开场：问题和责任边界

画面：首页总览，随后显示一张简洁对象流图。

口播：

> 大家好，我们是聚标成擎。BidPilot 不只是公告聚合页：情报人员确认检索口径，系统从真实来源固定证据，业务人员把值得跟进的项目转为有负责人和下一步动作的机会，审计复核人员能够回看来源、附件、版本和投递状态。系统不绕过付费、验证码或站点频率限制，也不会让模型补写没有证据的事实。

屏幕操作：依次高亮“检索—证据—机会工作台—订阅—报告历史”入口，不要点击未配置的第三方渠道。

## 0:30–1:25 问题一：从自然语言到证据

输入：

```text
最近一年广东省服务器招标信息
```

操作：

1. 展示意图确认卡：主题“服务器”、地域“广东”、时间范围、即时任务；如有字段不对，现场更正后再执行。
2. 展开检索计划：展示来源、最多两轮的有界查询计划与本地硬条件。
3. 执行真实任务；展示来源漏斗中的扫描、候选、保留、跳过/失败和淘汰原因。
4. 打开一条真实记录的原文链接或内置证据片段；依次指出标题、发布时间、采购人（若原文提供）、来源和附件（若原站提供）。
5. 展示同项目跨站版本/生命周期，而不是只展示一张结果卡。

口播：

> AI 只能建议查询词或在给定证据内复核。日期、地域、公告类型和排除词由本地规则硬校验。某个来源失败时，我们显示覆盖缺口，而不是把“没取到”写成“没有项目”。

## 1:25–1:55 证据报告与零结果的诚实表达

操作：下载本轮 Word，快速展示查询口径、来源覆盖、漏斗、原文链接、证据片段和附件字段。然后切换至已准备的真实零结果运行记录，展示诊断 Word 或漏斗中的来源状态与放宽建议。

口播：

> 每个结论都应能回到原文、来源或附件；没有附件就明确写“未发现”，不是补造。零结果也生成诊断，区分关键词过窄、来源跳过和来源异常。

## 1:55–2:40 千里马：服务器会话，不是权限绕过

画面：来源中心；遮挡任何账号和个人信息。若当天会话不可用，展示“需重新登录”状态和清除/重新登录入口，不伪造成功。

操作：

1. 展示千里马会话状态、最近验证或失效原因；不展示浏览器 profile、Cookie、凭据或内部用量账本。
2. 说明首次登录由用户本人在受保护的可见浏览器中完成。可用时，现场用一个用户主动的即时主题执行有界检索；不可用时，展示系统已停止增强的真实状态。
3. 只展示原站免费会员列表可见的结果字段；不点击付费详情，不翻阅凭据。

口播：

> 千里马的登录态保存在服务器专用的持久浏览器配置中，系统不导出 Cookie，也不通过 HTTP 重放。原站要求重新登录、会话失效、页面变化或预算受限时，本轮立即停止并如实显示。默认长期订阅仍使用公开来源；只有部署方已经获得千里马书面授权或官方 API 权利、完成变更登记后，才由管理员开启有界会员监控。这个开关不是授权证明，更不用于访问付费内容。

屏幕角标：`人工登录｜持久配置｜可失效｜可清除｜不越权`

## 2:40–3:25 机会工作台：从信息到可执行动作

操作：

1. 将刚才的真实标讯加入机会工作台。
2. 展示项目生命周期、来源证据与适配建议；说明“投/关注/跳过”是辅助判断而非中标承诺。
3. 现场设置或展示已保存的阶段、负责人、**下一步执行动作**、**下一步时间**、标签和备注；特别指出动作与日期是两个独立字段。
4. 展示买方观察项只来自已采集的真实公告证据。

口播：

> 这里回答的不只是“搜到什么”，还包括“谁下一步做什么、何时完成、依据是什么”。审计复核可以从机会卡回到原文、去重理由和版本时间线；没有来源支撑的结论不会写进卡片。

## 3:25–4:05 订阅、仅新增与五层评价

输入：

```text
最近3个月上海充电桩招标信息，每天早上9点汇总后发送给我
```

操作：

1. 展示订阅的时间、口径和至少一个已配置的安全交付目标；未配置的渠道不伪装投递成功。
2. 展示版本账本和逐目标 Outbox：仅新公告/新版本、成功/重试/死信的区别。
3. 打开“评价与验收”页或预置的五层矩阵：来源可用性、情报可信度、检索质量、工程可靠性、业务采用。

口播：

> 成功目标不会因另一个目标失败而重发。五层指标是 4 周真实试点的验收方法：来源可用性看覆盖缺口，情报可信度看能否回到原文，检索质量看硬条件，工程可靠性看恢复与投递，业务采用看真实人工流程的变化。我们不把演示数据或预设目标写成客户业绩。

## 4:05–4:40 Linux 企业部署：开放访问但不裸露端口

画面：部署拓扑图、`/health` 输出、systemd 状态或 Compose 服务状态；不得出现令牌、证书私钥或内网地址细节。

操作：

1. 展示 `enterprise` 部署拓扑：浏览器 → HTTPS Nginx/零信任网关 → 内部 BidPilot Web 与 worker。
2. 展示服务以专用非特权用户后台运行，以及 `/health` 正常；如使用 CI，展示本次提交的实际 run 状态与链接/编号。
3. 用屏幕标注企业模式四个同时成立的边界：精确 HTTPS Origin、受信客户端 CIDR、受信代理 CIDR、管理员令牌。

口播：

> 企业模式不是把 8000 端口放到公网。后端仅允许受信网关访问；代理头只接受明确受信的代理；所有业务 API——包括读取——都要求管理员令牌。生产证书、网关、防火墙和组织身份体系仍需在目标企业环境验收。

## 4:40–5:00 结尾：团队与交付承诺

画面：交付目录、详细设计、验收矩阵和代码仓库最新提交。

口播：

> 工程同事负责把多来源、调度、交付和跨平台运行做成可复现系统；审计学同事负责把证据链、授权状态、指标口径、Word 字段和提交清单变成可检查的控制点。BidPilot 的价值不在于给出一段看似完整的摘要，而在于让每个检索、动作和交付都能回到证据、权限边界和责任记录。
