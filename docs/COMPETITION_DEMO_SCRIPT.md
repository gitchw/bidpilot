# 标擎 BidPilot 40 强赛 Demo 录制脚本与分镜

建议时长：4 分 30 秒

目标：覆盖“输入→意图确认→真实检索→清洗去重→Word→定时增量→登录来源”的完整工作流，并展示多个问题。

原则：只展示真实运行；账号、手机号、Token、Cookie、数据库路径和未脱敏商业信息必须遮挡。

## 0:00–0:20 开场与命题对应

画面：标题页 + 首页总览。

口播：

> 大家好，我们是聚标成擎。标擎 BidPilot 面向超聚变招投标信息聚合命题，把一句自然语言编译成可审计的即时检索或长期订阅任务，从至少两个真实来源获取证据，完成清洗、硬过滤、跨站去重、Word 生成和仅新增推送。

屏幕角标：`证据优先｜10 个来源｜Word｜定时增量｜Windows/Linux/macOS`

## 0:20–1:15 问题一：正向多源检索

输入：

```text
最近一年广东省服务器招标信息
```

操作：

1. 展示意图确认卡：主题“服务器”、地域“广东”、时间范围、即时执行；
2. 展开检索计划，展示多来源、最多两轮、有界查询预算；
3. 执行任务；
4. 展示来源漏斗：扫描、候选、保留、淘汰理由；
5. 展示跨站去重和生命周期；
6. 打开一条原文链接，证明标题、发布时间、采购人和核心内容来自真实网页。

口播重点：AI 只能提出查询词或证据约束判断，地域、日期、排除词和最终字段由本地规则校验；单个来源失败不会拖垮整轮。

## 1:15–1:50 Word 输出

操作：

1. 点击下载本轮 Word；
2. 展示文件名“最近一年广东省服务器招标信息_时间.docx”；
3. 快速滚动执行摘要、查询口径、来源覆盖、重点标讯；
4. 指出每条都含标题、发布时间、来源链接、核心内容、附件链接（如有）。

口播：零结果也会生成诊断 Word；系统不把来源失败包装成没有项目。

## 1:50–2:25 问题二：零结果解释

输入：

```text
最近一年物业小区劳务购买服务招标信息
```

操作：展示 0 条结果、扫描→候选→保留漏斗、来源失败/跳过、淘汰原因和安全放宽建议。

口播：传统搜索的“0 条”无法判断是确实没有、关键词过窄还是来源异常；BidPilot 把这个不确定性显式呈现。

## 2:25–3:10 登录来源

画面：来源中心，敏感信息遮挡。

操作：

1. 展示中国招标投标网“授权已验证可用”，说明搜索与免费会员详情双重验证；
2. 展示千里马“授权已验证可用”；
3. 运行“服务器招标信息”即时任务，展示千里马首屏扫描 20 条、最终保留 3 条；
4. 明确不展示 Cookie、浏览器配置或账号资料。

口播：千里马由用户本人在系统托管的可见浏览器登录，不导出 Cookie，不交给 HTTP 客户端；仅即时、单主题、一次首屏，不定时、不翻页、不访问付费详情。

## 3:10–3:45 定时与仅新增

输入：

```text
最近3个月上海充电桩招标信息，每天早上9点汇总后发送给我
```

操作：

1. 确认每天 09:00 计划；
2. 选择两个投递目标（本地 + 已配置渠道）；
3. 展示订阅、下一次执行时间；
4. 展示 Outbox 的逐目标状态、有限重试与死信恢复；
5. 展示“仅新公告/新版本”账本。

口播：成功目标不会因为另一个目标失败而重发；worker 重启后仍能继续待发送任务。

## 3:45–4:10 机会与买方闭环

操作：

1. 将真实标讯加入机会工作台；
2. 展示阶段、负责人、下一步、标签和生命周期；
3. 展示企业能力画像与“投/关注/跳过”建议；
4. 打开买方雷达并创建监控。

口播：系统不是“搜完就结束”，而是把真实公告证据接到项目跟进和买方洞察。

## 4:10–4:30 跨平台与结尾

画面：测试审计报告、GitHub Actions 全绿、systemd 状态截图或终端录屏。

口播：

> 当前 288 项测试在 Windows 和 Debian 原生环境全部通过；GitHub 的 Windows、Ubuntu、macOS 双 Python 矩阵和 Ubuntu 容器构建 7 个作业全部通过。Linux 使用 systemd 以非特权用户后台运行。我们的核心创新不是让模型写一段漂亮摘要，而是让每个检索、判断和交付都能回到证据、边界与审计记录。

结束页：仓库地址、操作手册、Demo 公开链接位置。
